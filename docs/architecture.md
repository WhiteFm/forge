# Архитектура Forge

Forge — автономное React-приложение без серверного состояния. Оно развёртывается как статический сайт на GitHub Pages и не отправляет редактируемый контент на сервер.

```text
визуальные формы
  → ForgeProject в состоянии React
  → автоматическое сохранение ForgeProject в localStorage
  → normalizeProject: миграция, ID и внутренние ссылки
  → validateProject: ошибки и предупреждения
  → toCanonicalPack: переносимый .wsgpack
  → Character Creation List / будущий VTT
```

## 1. Границы ответственности

Forge:

- создаёт и редактирует определения контента;
- управляет EN/RU-локализацией;
- создаёт автоматические ID;
- описывает формулы, выборы, ресурсы и эффекты;
- проверяет структуру;
- экспортирует проект и канонический пак.

Forge не:

- хранит учётные записи пользователей;
- синхронизирует данные между устройствами;
- создаёт сохранение персонажа;
- выполняет полный расчёт персонажа или боя;
- проверяет лицензию юридически;
- гарантирует баланс и соответствие правилам.

## 2. Основные модули

| Файл | Ответственность |
|---|---|
| `src/App.tsx` | оболочка, навигация, поиск, локальное хранение, импорт/экспорт, инспектор |
| `src/EntityEditor.tsx` | формы девяти типов сущностей |
| `src/components.tsx` | общие визуальные редакторы, уровни, таблица, выборы и эффекты |
| `src/VisualRuleBuilder.tsx` | визуальные выражения, операнды, операторы и выбор сущностей |
| `src/types.ts` | контракт редактируемого ForgeProject |
| `src/data.ts` | начальные значения, автоматические ID и нормализация/миграция |
| `src/validation.ts` | проверка проекта и канонизация `.wsgpack` |
| `src/ui-i18n.tsx` | язык интерфейса и функция переводов |

| `scripts/` | генераторы и миграторы массовых данных |

## 3. Состояние и сохранение

Ключ браузера: `wsguild.forge.project.v1`.

При запуске приложение:

1. читает JSON из `localStorage`;
2. проверяет минимальное наличие `pack` и массива `entities`;
3. нормализует найденный проект;
4. при ошибке использует пустой `initialProject`.

Каждое изменение состояния записывает проект обратно с новым `updatedAt`. Серверной базы данных в Forge нет.

## 4. Нормализация

`normalizeProject()` — граница совместимости редактора. Она:

- принимает старые проекты;
- удаляет устаревшие поля;
- присваивает схему 2.0.0;
- создаёт ID из Pack ID, типа и английского имени;
- разрешает коллизии суффиксами;
- глубоко обновляет ссылки;
- синхронизирует классовые уровни и таблицы;
- нормализует подсущности и денежные значения.

Нормализация выполняется:

- при загрузке из localStorage;
- при импорте;
- после изменения английского имени или коллекций подсущностей;
- после нажатия Done в настройках пака;
- перед скачиванием `.forge.json`.

## 5. Валидация

`validateProject()` является чистой функцией: она не меняет проект и возвращает `ValidationIssue[]`.

```ts
{
  severity: "error" | "warning",
  entityId?: string,
  path: string,
  message: string
}
```

Сообщения создаются по-русски и переводятся на английский при выбранном EN. Ошибки блокируют только экспорт `.wsgpack`; проект `.forge.json` можно скачать в любом состоянии.

## 6. Канонизация

`toCanonicalPack()` отделяет технические данные от локализации и переводит редакторские значения эффектов в типизированную форму.

Канонизация намеренно не удаляет `draft` или `deprecated`: решение о публикационном фильтре пока остаётся автору/будущей версии контракта.

## 7. Локализация

Есть два независимых слоя:

- технический интерфейс — JSON-словари `src/i18n/en.json` и `ru.json`;
- контент — `entity.localization.en/ru`, выносимый в отдельные словари `.wsgpack`.

Английский — язык по умолчанию. Добавление нового языка потребует:

1. расширить тип `Locale`;
2. добавить словарь интерфейса;
3. добавить локализацию каждой сущности;
4. расширить `toCanonicalPack()` и список `manifest.locales`;
5. обновить валидацию обязательных названий.

## 8. Безопасность выражений

Forge не выполняет строки формул через `eval`. Он ограничивает алфавит и набор функций, а визуальный конструктор сохраняет структурированный AST-подобный `RuleExpression`.

Фактический вычислитель должен быть реализован в CCL/VTT и обязан:

- интерпретировать только разрешённые операнды и функции;
- не исполнять произвольный код;
- использовать детерминированный порядок эффектов;
- ограничивать деление на ноль, NaN и переполнение;
- валидировать входной пак повторно на своей стороне.

## 9. Принципы модели

- ID отделены от локализованного текста, хотя текущий редактор генерирует ID из английского имени.
- Официальные данные создаются теми же формами, что и homebrew.
- Каждый независимый бонус или владение задаётся атомарным эффектом.
- Ограниченное умение описывает ресурс, максимум и восстановление.
- Класс хранит отдельные владения при старте и мультиклассировании.
- Выбор разделён на допустимые варианты и применение результата.
- Материальный компонент заклинания является предметом инвентаря.
- Ошибки блокируют экспорт, предупреждения требуют решения автора.
- Проект и готовый контент-пак экспортируются разными файлами.

## 10. Сборка и публикация

Проект использует React, TypeScript и Vite. Основные проверки:

```bash
pnpm test
pnpm run build
```

`pnpm run build` сначала запускает TypeScript без генерации файлов, затем создаёт статический `dist/`. После отправки в ветку `main` GitHub Actions публикует сборку на GitHub Pages с доменом `forge.wsguild.net`.
