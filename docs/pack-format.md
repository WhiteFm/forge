# Форматы, ID, локализация и переносимость

## 1. Два файла для двух задач

Forge использует два связанных, но не взаимозаменяемых формата.

| Формат | Назначение | Повторное редактирование |
|---|---|---|
| `pack_id.forge.json` | полный рабочий проект | да, импортируется в Forge |
| `pack_id-version.wsgpack` | канонический пакет для CCL/VTT | нет в текущей версии Forge |

Никогда не храните только `.wsgpack`, если хотите продолжать редактирование.

## 2. Редактируемый ForgeProject

Верхний уровень:

```json
{
  "schemaVersion": "2.0.0",
  "pack": {},
  "entities": [],
  "updatedAt": "2026-08-11T00:00:00.000Z"
}
```

### `schemaVersion`

Версия структуры, а не версия контента. Текущая версия — `2.0.0`.

### `pack`

```json
{
  "id": "my_pack",
  "version": "1.0.0",
  "name": "My Pack",
  "rulesetId": "dnd5e.2024",
  "licenseId": "license.homebrew",
  "author": "Author",
  "defaultLocale": "en",
  "attribution": "Optional attribution text"
}
```

В текущем окне проекта редактируются `id`, `version`, `name`, `rulesetId`, `licenseId`, `author`. `defaultLocale` и `attribution` поддерживаются моделью и сохраняются при импорте, но пока не имеют отдельных полей в интерфейсе.

### `entities`

Массив всех сущностей. Локализация хранится внутри каждой сущности, чтобы редактор мог менять EN/RU рядом с техническими полями.

### `updatedAt`

Метка последнего обновления. При автосохранении в браузер записывается текущее время; экспорт проекта также проходит через нормализацию.

## 3. Канонический `.wsgpack`

Верхний уровень:

```json
{
  "manifest": {},
  "entities": [],
  "localizations": {
    "en": {},
    "ru": {}
  },
  "assets": []
}
```

### Manifest

| Поле | Источник/назначение |
|---|---|
| `schemaVersion` | версия схемы проекта |
| `packId` | Pack ID |
| `namespace` | вычисляется из первых частей Pack ID |
| `version` | версия контента |
| `rulesetId` | набор правил |
| `kind` | `official` только для Pack ID `srd52`, иначе `homebrew` |
| `author` | автор |
| `defaultLocale` | `en`, если не указано другое |
| `locales` | сейчас всегда `en`, `ru` |
| `license` | ID, отображаемое имя и атрибуция лицензии |
| `portability` | флаги переносимости технических и локализованных данных |
| `createdAt` | `updatedAt` проекта |

Флаги переносимости текущей версии:

```json
{
  "embedTechnicalData": true,
  "embedLocalizedText": true,
  "allowDerivativePacks": true,
  "requiresEntitlement": false
}
```

Это декларация формата. Юридические права определяются фактической лицензией и материалами пака.

### Entities

В канонической сущности поле `localization` удаляется. Некоторые редакторские имена нормализуются:

- `spellLevel` экспортируется как `level`;
- `featCategory` экспортируется как `category`;
- у справочника `referenceCategory` становится `category`, а `referenceValue` — `value`;
- эффекты получают типизированное каноническое `value` и вложенную `duration`.

Остальные технические поля сохраняются, включая автоматические ID и ссылки.

### Localizations

Текст разделяется на словари:

```json
{
  "en": {
    "my_pack.feature.example": {
      "name": "Example",
      "description": "..."
    }
  },
  "ru": {
    "my_pack.feature.example": {
      "name": "Пример",
      "description": "..."
    }
  }
}
```

Это позволяет:

- добавлять новые языки без изменения механики;
- загружать только нужный язык;
- гарантировать, что перевод не повлияет на математику;
- использовать один ID во всех приложениях.

### Assets

Сейчас экспортируется пустой массив. В будущем он предназначен для изображений, иконок и других переносимых ресурсов. Текущая версия не упаковывает бинарные файлы внутрь `.wsgpack`.

## 4. Правила ID

### Pack ID

Регулярное правило:

```text
^[a-z][a-z0-9_]*$
```

Допустимо: `srd52`, `my_pack2`. Недопустимо: `My Pack`, `52pack`, `my-pack`.

### Entity/Subentity ID

ID должен:

- начинаться со строчной латинской буквы;
- содержать несколько частей, разделённых `.`, `_` или `-`;
- не содержать пробелов;
- быть уникальным в паке.

Forge сам создаёт ID по шаблону:

```text
{packId}.{entityType}.{englishSlug}
{entityId}.{subentityEnglishSlug}
```

Примеры:

```text
srd52.class.wizard
srd52.subclass.evoker
srd52.background.criminal.equipment_set_a
srd52.feat.alert.initiative_bonus
```

### Нормализация имени

Алгоритм:

1. Unicode NFKD и удаление диакритики.
2. Нижний регистр.
3. Удаление точек и апострофов.
4. Любая другая группа не-латинских символов становится `_`.
5. `_` по краям удаляются.
6. Пустой результат заменяется резервным машинным именем.

Например:

```text
"Mage's Armor 2.0" → "mages_armor_20"
"Choice 1" → "choice_1"
```

Кириллическое имя не используется для ID. Если английское имя состоит только из символов, исчезающих при нормализации, будет использован fallback.

## 5. Изменение ID и совместимость

Во время нормализации Forge строит карту старых и новых ID и глубоко заменяет точные ссылки и дочерние префиксы внутри проекта.

Это защищает внутренние связи, но не может изменить:

- уже экспортированные сохранения персонажей;
- другие паки, хранящие ссылку на старый ID;
- файлы и приложения вне текущего проекта.

Поэтому после публикации ID следует считать неизменяемым. Переименование английского отображаемого имени, которое должно сохранить совместимость, в будущей схеме потребует отдельного стабильного slug/alias. Текущая версия автоматически меняет ID вместе с английским именем.

Если несовместимое переименование необходимо:

1. увеличьте MAJOR-версию пака;
2. сохраните таблицу миграции `old_id → new_id` вне Forge;
3. по возможности оставьте старую сущность `deprecated`;
4. обновите потребителей и сохранения персонажей.

## 6. Удалённые устаревшие поля

При нормализации удаляются:

- верхнеуровневый `projectId`;
- `pack.sourceId`;
- теги сущности;
- `rulesetId`, `sourceId`, `sourceVersion`, `licenseId` внутри сущностей;
- старый `creatureTypeId`;
- некоторые старые поля предыстории после миграции.

Ruleset, лицензия, источник и авторство должны находиться в информации по паку. Теги не входят в текущую модель.

## 7. Миграция старого проекта

`normalizeProject()` выполняет следующие преобразования:

- устанавливает `schemaVersion: 2.0.0`;
- приводит Pack ID к допустимому slug;
- заполняет отсутствующие настройки пака;
- генерирует уникальные ID всех сущностей;
- заменяет ссылки по всему проекту;
- ограничивает класс двадцатью уровнями и перенумеровывает их с 1;
- синхронизирует строки таблицы класса;
- нормализует размеры вида и создаёт отсутствующие чувства;
- переносит старую черту и владения предыстории в слоты;
- ограничивает денежные значения;
- перестраивает ID выборов, комплектов, эффектов и групп материалов;
- удаляет фильтры на устаревших тегах.

Миграция не может восстановить смысл поля, которого не было в старых данных. После импорта всегда проверьте весь пак.

## 8. Ссылки между сущностями

Forge использует ссылки по ID вместо копирования сущностей. Основные связи:

- класс/подкласс/вид/черта → умения;
- подкласс → базовый класс;
- предыстория → черты, навыки, инструменты, умения и предметы;
- умение → заклинания;
- предмет-контейнер → вложенные предметы;
- заклинание → классы и предметы материальных компонентов;
- выбор → допустимые сущности;
- эффект `reference` → другая сущность.

Преимущества:

- одна сущность хранится один раз;
- исправление имени или механики применяется всем потребителям;
- сохранение персонажа может хранить ID и при необходимости встраивать технический снимок.

## 9. Портативность сохранений персонажей

Контент-пак и сохранение персонажа — разные файлы. Для надёжного переноса CCL/VTT должен сохранять:

- ID и версию пака;
- ID выбранных сущностей и подсущностей;
- результаты всех выборов;
- текущие значения ресурсов;
- вычисленные или исходные значения характеристик;
- при необходимости встроенный технический snapshot сущностей;
- локализованный текст или ссылку на нужную локализацию.

Текущий `.wsgpack` создаёт необходимую основу: стабильные ID, технические данные, локализации и манифест. Формат самого сохранения персонажа разрабатывается в CCL и не создаётся Forge.

## 10. Внешние ссылки и зависимости пака

Валидация допускает без предупреждения некоторые внешние префиксы:

```text
skill.
tool.
language.
weapon.
armor.
save.
```

Также ссылки `srd52.*` считаются допустимой зависимостью от SRD, даже если сущность не встроена в текущий пак.

Для полностью автономного homebrew-пака предпочтительно включать необходимые справочники и сущности внутрь пака. В будущем манифесту потребуется явный список зависимостей и их версий; текущая модель его пока не содержит.

## 11. Лицензирование

Forge сохраняет технические метаданные, но не проверяет юридическую допустимость контента.

Автор пака обязан:

- указать корректный `licenseId`;
- заполнить автора и при необходимости атрибуцию;
- не включать материалы, на которые нет прав;
- соблюдать условия SRD и других лицензий;
- не считать флаг `kind: official` доказательством официальной лицензии.

Для SRD 5.2.1 в репозитории используется CC BY 4.0 и соответствующая атрибуция.
