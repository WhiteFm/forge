# Формулы, выборы, ресурсы и эффекты

## 1. Главный принцип

Forge разделяет:

- текст для человека;
- структурированное правило для программы.

Фраза «вы можете добавить бонус мастерства к инициативе» в описании ничего не меняет сама по себе. Для расчёта нужен эффект:

```text
target: combat.initiative
operation: add
value: proficiency_bonus()
activation: always_on
```

Одно независимое механическое изменение следует хранить как один атомарный эффект. Так проще искать конфликты, определять порядок применения и переносить правило между CCL и VTT.

## 2. Визуальный конструктор выражений

Конструктор показывает последовательность операндов и операторов. Пользователь выбирает сущности и подготовленные типы значений, а Forge параллельно сохраняет:

- строку выражения для совместимости;
- `RuleExpression` — структурированную модель без необходимости разбирать свободный код.

### Операнды

| `kind` | Что означает | Пример компиляции |
|---|---|---|
| `number` | число | `8` |
| `boolean` | логическое значение | `true` |
| `ability_score` | значение характеристики | `ability_score("str")` |
| `ability_modifier` | модификатор характеристики | `ability_modifier("con")` |
| `proficiency_bonus` | бонус мастерства | `proficiency_bonus()` |
| `character_level` | общий уровень персонажа | `character_level()` |
| `class_level` | уровень выбранного класса | `class_level("srd52.class.wizard")` |
| `entity` | ссылка на сущность пака | `"srd52.feature.example"` |
| `selected_value` | значение, выбранное игроком | `selected_value("key")` |
| `legacy` | сохранённое старое выражение | исходная строка |

`legacy` предназначен для миграции старых данных. Для нового контента используйте подготовленные операнды.

### Арифметические операторы

`+`, `-`, `*`, `/`.

### Операторы условий

`==`, `!=`, `>`, `>=`, `<`, `<=`, `contains`, `and`, `or`.

### Разрешённые функции

Валидация допускает только:

| Функция | Назначение |
|---|---|
| `character_level()` | общий уровень персонажа |
| `class_level("id")` | уровень указанного класса |
| `ability_score("str")` | значение характеристики |
| `ability_modifier("str")` | модификатор характеристики |
| `proficiency_bonus()` | бонус мастерства |
| `has_feature("id")` | наличие умения; поддерживается валидатором и импортированными выражениями |
| `min(a,b)` | минимум |
| `max(a,b)` | максимум |
| `floor(x)` | округление вниз |
| `ceil(x)` | округление вверх |
| `abs(x)` | абсолютное значение |

Примеры:

```text
8 + ability_modifier("con")
class_level("srd52.class.wizard")
ability_score("int") >= 13
max(1, proficiency_bonus())
```

В строках разрешены латинские буквы, цифры, пробелы, `_`, круглые скобки, точки, запятые, кавычки и математические/сравнительные операторы. Произвольный JavaScript и вызовы неизвестных функций запрещены.

### Порядок вычисления

Строка компилируется с обычной записью операторов. Чтобы правило не зависело от предположений о приоритете, явно группируйте сложные части скобками. Визуальная модель сохраняет порядок операндов и операторов, но фактическое вычисление выполняет CCL/VTT.

## 3. Условия и требования

Условные выражения используются для:

- мультиклассирования;
- prerequisites черт и умений;
- requirements предметов;
- условий отдельных эффектов;
- фильтров вариантов выбора.

Несколько записей в списке условий обычно означают, что потребитель должен проверить каждую запись. Логика внутри одной записи задаётся `and` или `or`.

Не записывайте условие только текстом. Если условие пока невозможно автоматизировать, сохраните максимально точную структурированную часть и выставьте `automationLevel: partial` или `manual`.

## 4. Выборы игрока

`ChoiceDefinition` описывает не результат, а пространство допустимого выбора.

| Поле | Назначение |
|---|---|
| `id` | автоматический ID выбора |
| `name` | английское имя, формирующее ID |
| `nameRu` | русское имя |
| `selectionType` | тип результата |
| `min` | минимальное количество выбранных значений |
| `max` | максимальное количество выбранных значений |
| `optionIds` | явный список допустимых сущностей |
| `filter` | условие для динамического отбора |
| `filterExpression` | структурированная версия фильтра |

### Типы выбора

| Значение | Результат |
|---|---|
| `entity` | одна или несколько сущностей пака |
| `reference` | справочное значение/ID |
| `number` | число |
| `text` | свободный текст игрока |

Для ограниченного списка сущностей заполняйте `optionIds`. Для динамического множества используйте фильтр. Пустые `optionIds` без фильтра не задают полезного множества вариантов.

`min = max = 1` означает один обязательный выбор. `min = 0` делает выбор необязательным. `max` не должен быть меньше `min` по смыслу, даже если текущая валидация не проверяет это отдельно.

## 5. Применение результата выбора

Определение выбора отвечает на вопрос «что можно выбрать». `ChoiceApplication` отвечает на вопрос «куда записать результат».

В интерфейсе это поле **After the player chooses / После выбора игрока**.

Подготовленные применения:

| Цель | Действие |
|---|---|
| `features.granted` | выдать выбранные умения |
| `feats.granted` | выдать выбранные черты |
| `proficiencies.skills` | выдать владение навыком |
| `proficiencies.tools` | выдать владение инструментом |
| `inventory.items` | добавить выбранные предметы |
| `languages.known` | выдать выбранные языки |

Техническая запись содержит:

```json
{
  "choiceId": "srd52.species.dragonborn.ancestry",
  "target": "features.granted",
  "operation": "grant",
  "valueTemplate": "selected_entity_id"
}
```

`selected_entity_id` означает: подставить ID сущности, выбранной игроком. Для владений используется `grant_proficiency`, для остальных подготовленных целей — `grant`.

Если выбрать «Do not apply automatically / Не применять автоматически», выбор сохранится, но потребитель должен обработать его вручную. Удаление Choice автоматически удаляет его ChoiceApplication.

## 6. Выборы и комплекты снаряжения

`equipmentOptions[].choiceItems[]` связывает ранее сделанный выбор с предметом стартового комплекта:

```json
{
  "choiceId": "homebrew.background.sailor.tool_choice",
  "quantity": 1
}
```

Это не новая копия выбора. Это указание: добавить в комплект результат существующего выбора в заданном количестве.

## 7. Атомарный эффект

Эффект отвечает на вопросы:

1. Что меняется?
2. Каким способом?
3. На какое значение?
4. Когда это действует?
5. При каких условиях?
6. Как складывается с другими источниками?
7. Сколько длится?
8. Можно ли применить автоматически?

### ID и имя

ID эффекта строится из ID сущности и английского имени эффекта. Имена можно редактировать в заголовке карточки. ID внутри одной сущности обязан быть уникальным.

### Target / Цель

Цель — путь в модели персонажа или игрового состояния. Он должен содержать минимум две части через точку.

Подготовленные цели:

#### Характеристики

```text
abilities.str.score
abilities.dex.score
abilities.con.score
abilities.int.score
abilities.wis.score
abilities.cha.score
```

#### Бой

```text
combat.initiative
combat.armor_class
combat.hit_points.current
combat.hit_points.maximum
combat.temporary_hit_points
combat.target.hit_points.current
combat.area.targets.hit_points.current
combat.saving_throws.*
combat.attacks.*.bonus
```

#### Навыки и владения

```text
skills.*.proficiency
skills.*.checks
proficiencies.weapons
proficiencies.armor
proficiencies.tools
```

#### Передвижение и чувства

```text
movement.walk
movement.fly
movement.swim
movement.climb
movement.burrow
senses.darkvision
```

#### Защиты

```text
defenses.resistances
defenses.immunities
defenses.vulnerabilities
```

#### Заклинания и инвентарь

```text
spellcasting.save_dc
spellcasting.attack_bonus
spellcasting.slots.*
spellcasting.prepared.spells
spellcasting.spellbook.spells
inventory.carry_capacity
inventory.items
inventory.currency
```

`*` обозначает множество элементов. Например, `combat.area.targets.hit_points.current` относится ко всем целям области, а не к самому заклинателю.

### Operation / Операция

| Значение | Смысл |
|---|---|
| `add` | прибавить значение |
| `subtract` | вычесть значение |
| `set` | установить значение |
| `set_minimum` | установить нижнюю границу |
| `set_maximum` | установить верхнюю границу |
| `multiply` | умножить |
| `replace_formula` | заменить формулу вычисления |
| `grant` | выдать сущность/значение |
| `grant_proficiency` | выдать владение |
| `upgrade_proficiency` | повысить уровень владения |
| `grant_advantage` | дать преимущество |
| `grant_disadvantage` | дать помеху |
| `create_resource` | создать ресурс |
| `restore_resource` | восстановить ресурс |

Выбирайте наиболее узкую операцию. Не имитируйте владение через `add`, если существует `grant_proficiency`.

### Value type / Тип значения

| Значение | Содержимое |
|---|---|
| `number` | обычное число |
| `boolean` | `true` или `false` |
| `string` | строковое значение |
| `formula` | безопасное выражение |
| `dice` | запись кости, например `2d6` |
| `reference` | ID другой сущности |

При экспорте канонического пака тип сохраняется явно: число становится числом, boolean — логическим значением, формула — объектом `{type: "formula", expression: ...}`, кость — `{type: "dice", dice: ...}`, ссылка — `{type: "reference", reference: {id: ...}}`.

### Activation / Режим

| Значение | Когда действует |
|---|---|
| `always_on` | постоянно |
| `manual_unlimited` | после ручного объявления, без лимита |
| `limited_use` | после траты ресурса |
| `equipped` | пока предмет экипирован |
| `attuned` | пока предмет настроен |
| `on_event` | при событии в `trigger` |

### Action cost

`none`, `action`, `bonus_action`, `reaction`, `free_action`, `special`.

### Trigger

Событие, запускающее эффект, например «when a creature ends its turn in the area». Текущее поле хранится строкой и требует согласованного словаря событий в потребляющем приложении. Если триггер нельзя выполнить автоматически, используйте `partial` или `manual`.

### Conditions

Список безопасных условных формул. Все необходимые игровые ограничения должны находиться здесь или в структурированных полях сущности, а не только в Notes.

### Stacking / Сложение

| Значение | Правило |
|---|---|
| `sum` | сложить значения |
| `maximum` | оставить максимальное |
| `minimum` | оставить минимальное |
| `replace` | заменить предыдущий результат |
| `non_stacking` | одинаковые эффекты не складываются |
| `unique_by_source` | один эффект от одного источника |

Для `non_stacking` и `unique_by_source` задайте `stackingGroup`, например `initiative_proficiency_bonus`. Без группы Forge выдаёт предупреждение.

### Priority / Приоритет

Число определяет порядок обработки, когда операции зависят друг от друга. Базовое значение — `100`. Рекомендуемая договорённость:

- 0–49 — создание базовых значений и ресурсов;
- 50–99 — замены и границы;
- 100–149 — обычные бонусы;
- 150+ — итоговые модификаторы и временные эффекты.

Это соглашение проекта; потребитель должен явно реализовать сортировку по `priority`.

### Resource ID

Обязателен для ограниченного эффекта и восстановления ресурса. Ссылка должна вести на ресурс умения или предмета, который реально существует в паке/состоянии персонажа.

### Duration / Длительность

| Значение | Дополнительные данные |
|---|---|
| `instant` | мгновенно |
| `rounds` | `durationValue` в раундах |
| `minutes` | `durationValue` в минутах |
| `hours` | `durationValue` в часах |
| `until_rest` | `restType`: `short` или `long` |
| `permanent` | постоянно |

### Automation level

- `full` — все необходимые данные структурированы;
- `partial` — автоматизируется только известная часть;
- `manual` — эффект требует решения человека.

### Notes

Notes поясняет реализацию, исключения и спорные случаи разработчику или ведущему. Notes не участвует в расчёте.

## 8. Ресурсы и восстановления

Ресурс — отдельный счётчик, например применения Arcane Recovery.

Пример:

```text
maximum = 1
recovery = long_rest
recoveryFormula = 1
```

Для ресурса, равного бонусу мастерства:

```text
maximum = proficiency_bonus()
recoveryFormula = proficiency_bonus()
```

Различайте:

- максимум ресурса;
- текущее значение, которое хранит персонаж/VTT;
- количество восстановления;
- событие восстановления.

Forge описывает максимум и восстановление, но текущее значение относится к сохранению персонажа, а не контент-паку.

## 9. Периодический урон и лечение

Для заклинаний используйте одновременно:

- `spellProfiles[]` для типовых костей начального и периодического эффекта;
- `effects[]` для точной цели, операции, условий, триггера и длительности.

Пример урона в области в конце хода:

```text
target: combat.area.targets.hit_points.current
operation: subtract
valueType: dice
value: 2d6
activation: on_event
trigger: end_of_turn_in_area
duration: rounds
```

Пример лечения:

```text
target: combat.target.hit_points.current
operation: add
valueType: formula
value: 1d8 + ability_modifier("wis")
activation: manual_unlimited или limited_use
```

Если значение содержит кость и арифметику, текущий безопасный конструктор формул не является полноценным dice-parser. Для автоматизации рекомендуется хранить кости в `spellProfiles` или `valueType: dice`, а фиксированные модификаторы — отдельным атомарным эффектом.

## 10. Защита от математических ошибок

Перед публикацией проверьте:

- один и тот же бонус не выдан одновременно напрямую и через связанное умение;
- `add` не используется там, где требуется `set_minimum` или `maximum`;
- бонус мастерства не продублирован несколькими источниками без корректной `stackingGroup`;
- все ограниченные эффекты ссылаются на ресурс;
- формула использует разрешённые функции и сбалансированные скобки;
- цель отличает самого персонажа, одну цель и все цели области;
- уровень в формуле — именно `character_level` или нужный `class_level`;
- восстановление не превышает максимум, если потребитель не ограничивает его автоматически;
- текст и структурированная механика не противоречат друг другу.

Валидация проверяет структуру, но не доказывает соответствие правилам D&D. Финальная проверка игрового смысла остаётся обязанностью автора пака.
