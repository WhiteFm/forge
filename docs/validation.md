# Валидация и поиск ошибок

## 1. Ошибка и предупреждение

### Error / Ошибка

Ошибка означает, что пакет структурно небезопасен для автоматического потребителя. Пока есть ошибки:

- кнопка экспорта `.wsgpack` отключена;
- рядом с сущностью показывается число ошибок;
- индикатор технического состояния уменьшается.

### Warning / Предупреждение

Предупреждение означает потенциально неоднозначную или внешнюю зависимость. Экспорт разрешён, но автор должен осознанно проверить ситуацию.

## 2. Область проверки

В инспекторе можно выбрать:

- **Whole pack / Весь пакет** — все проблемы;
- **Current record / Текущая запись** — текущая сущность и общие проблемы манифеста.

Нажатие на карточку проблемы открывает связанную сущность. Подпись содержит:

- сообщение;
- ID сущности или `manifest`;
- технический путь поля, например `effects.0.value`.

Пути массивов нумеруются с нуля: `effects.0` — первый эффект.

## 3. Проверки пака

### Pack ID

Требование: строчная латинская буква в начале, затем строчные буквы, цифры или `_`.

Исправление: откройте настройки проекта, измените Pack ID и нажмите Done.

### Version

Требование: SemVer `1.0.0`, при необходимости с суффиксом вроде `1.0.0-beta.1`.

## 4. Общие проверки сущностей

### Формат ID

ID должен содержать namespace, тип и машинное имя. В нормальном процессе он создаётся автоматически; ручное редактирование JSON может нарушить формат.

### Уникальность ID

Два объекта не могут иметь одинаковый ID. Нормализация обычно добавляет `_2`, но после ручного изменения JSON возможен конфликт.

### Локализация

Обязательны:

- `localization.en.name`;
- `localization.ru.name`.

Описания могут быть пустыми, хотя опубликованный контент рекомендуется снабжать обоими описаниями.

### Формулы prerequisites

Каждая формула должна:

- быть непустой;
- содержать только разрешённые символы;
- иметь сбалансированные скобки;
- использовать только разрешённые функции.

## 5. Проверки класса

| Проверка | Как исправить |
|---|---|
| от 1 до 20 уровней | добавьте или удалите уровни |
| уровни идут подряд с 1 | используйте только кнопки добавления/удаления; повторно нормализуйте проект |
| строк таблицы столько же, сколько уровней | изменение уровней синхронизирует таблицу автоматически |
| в каждой строке 9 значений ячеек | вставьте полный диапазон или повторно нормализуйте проект |
| выбрана минимум одна основная характеристика | отметьте Primary abilities |
| заклинательный класс имеет характеристику | выберите Spellcasting ability или поставьте `casterProgression: none` |

## 6. Проверки подкласса

Подкласс обязан иметь `classId`, указывающий на базовый класс. Выберите класс в раскрывающемся списке.

Текущая валидация проверяет наличие значения `classId`, но отдельная общая проверка ссылки также поможет обнаружить удалённый класс.

## 7. Проверки предыстории

Предыстория должна:

- предлагать ровно три характеристики;
- иметь `abilityScoreIncrease`;
- хранить те же три разрешённые характеристики;
- иметь минимум одну схему распределения.

Пустые слоты черт, навыков, инструментов и умений допустимы: они означают выбор игроком позже.

## 8. Проверки ограниченного умения

Умение `limited_use` должно иметь:

- Resource ID;
- формулу максимума;
- тип восстановления;
- формулу восстановления.

Текущая обязательная проверка явно контролирует ID и формулу максимума. Не полагайтесь только на неё — заполните и восстановление.

## 9. Проверки предмета

| Проверка | Требование |
|---|---|
| вес | неотрицательный |
| стоимость | 0–999999 cp |
| оружие | существует `weaponProfile` |
| доспех/щит | существует `armorProfile` |
| requirements | каждая формула валидна |

Переключение типа предмета через интерфейс автоматически создаёт начальный профиль оружия или доспеха.

## 10. Проверки заклинания

| Проверка | Требование |
|---|---|
| уровень | 0–9 |
| школа | заполнен `schoolId` |
| дистанция | при `range.type: distance` значение больше 0 |
| материал | текст материального компонента связан хотя бы с одной группой |
| группа материалов | содержит хотя бы один предмет |
| предмет материала | существует в текущем паке и имеет тип `item` |
| количество | не меньше 1 |

Если заклинание требует несколько альтернативных наборов материалов, создайте отдельные группы. Если нужны все предметы одновременно, поместите их в одну группу.

## 11. Проверки эффекта

### Effect ID

Должен быть стабильным техническим идентификатором и не дублироваться внутри сущности.

### Target

Должен быть путём вида `combat.initiative`, то есть начинаться с буквы и содержать части через точку.

### Value

Не может быть пустым. Если тип `formula`, дополнительно выполняется проверка безопасной формулы.

### Conditions

Каждое условие проверяется как безопасная формула.

### Resource

Эффект с `activation: limited_use` должен ссылаться на ресурс. Для операции `restore_resource` Resource ID также необходим по смыслу модели, но текущая проверка операции отдельно этого не гарантирует — проверьте поле вручную.

### Stacking group

Для `non_stacking` и `unique_by_source` пустая группа вызывает предупреждение. Заполните общий стабильный ключ для эффектов, которые должны сравниваться друг с другом.

## 12. Проверки применений выбора

Каждый `ChoiceApplication.choiceId` должен соответствовать существующему `choices[].id` той же сущности.

Обычная причина ошибки — ручное удаление выбора в JSON без удаления его применения. В интерфейсе удаление выполняется атомарно и убирает обе записи.

## 13. Проверка ссылок

Forge собирает ссылки из:

- `featureIds`;
- уровней класса и подкласса;
- `classId`;
- `featIds`;
- слотов навыков, инструментов и умений предыстории;
- `spellGrants`.

Если ID не найден, создаётся предупреждение, кроме:

- ссылок `srd52.*`;
- внешних префиксов `skill.`, `tool.`, `language.`, `weapon.`, `armor.`, `save.`.

Важно: текущая проверка не обходит абсолютно каждое возможное поле ссылки, например все варианты внутри эффектов, комплектов и расширенных импортированных данных. Перед публикацией дополнительно проверяйте JSON и фактический импорт в CCL.

## 14. Что валидация пока не проверяет

Текущая версия не гарантирует:

- соответствие текста официальным правилам D&D;
- корректность игрового баланса;
- отсутствие двойной выдачи одного бонуса разными умениями;
- `min <= max` у каждого выбора;
- корректность типа каждой цели эффекта относительно типа значения;
- существование всех ссылок во всех вложенных полях;
- уникальность всех подсущностей на уровне всего пака;
- согласованность `spellProfiles`, `effects` и текстового описания;
- юридическую допустимость содержимого;
- поддержку каждого target/trigger конкретной версией CCL/VTT.

Ноль ошибок означает структурно экспортируемый пакет, а не автоматически доказанный правильный контент.

## 15. Рекомендуемая финальная проверка

1. Исправьте все ошибки манифеста.
2. Переключитесь на Whole pack.
3. Исправьте ошибки сущностей сверху вниз.
4. Просмотрите каждое предупреждение и запишите принятое решение.
5. Проверьте английские и русские названия/описания.
6. Проверьте стабильность опубликованных ID.
7. Сверьте эффекты с текстом правил.
8. Скопируйте канонический JSON нескольких сложных сущностей и проверьте типы значений.
9. Скачайте резервный `.forge.json`.
10. Экспортируйте `.wsgpack`.
11. Импортируйте пак в тестовую версию CCL и проверьте расчёты на контрольном персонаже.
