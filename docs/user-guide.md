# Руководство пользователя Forge

## 1. Назначение

WSGuild Forge («Кузница») — браузерный визуальный редактор официального и homebrew-контента D&D 5.5e. В нём можно собрать единый пакет классов, подклассов, видов, предысторий, черт, умений, предметов, заклинаний и справочных значений.

Forge решает четыре задачи:

- позволяет создавать контент без ручного редактирования JSON;
- отделяет локализованный текст от технической механики;
- проверяет ссылки, обязательные поля и безопасные формулы;
- экспортирует переносимый пакет для CCL и будущего VTT.

Forge не является листом персонажа и не выполняет полноценный игровой расчёт. Он описывает данные и правила, которые применит потребляющее приложение.

## 2. Первый запуск

Откройте [forge.wsguild.net](https://forge.wsguild.net/). Английский язык интерфейса используется по умолчанию. Переключатель `EN/RU` меняет:

- язык кнопок и технических подписей;
- редактируемый язык названия и описания текущей сущности;
- язык сообщений валидации.

Переключение языка не создаёт копию сущности и не меняет её механику.

## 3. Где хранятся изменения

Каждое изменение автоматически записывается в `localStorage` браузера для домена Forge.

Практические последствия:

- после перезагрузки страницы проект остаётся;
- проект не синхронизируется между компьютерами и браузерами;
- очистка данных сайта, приватный режим или смена устройства могут удалить локальную копию;
- для резервной копии регулярно скачивайте файл проекта кнопкой **Project / Проект**.

Автосохранение не заменяет резервную копию.

## 4. Основные области интерфейса

### Верхняя панель

- логотип Forge;
- карточка текущего пака — открывает настройки проекта;
- состояние локального сохранения;
- переключатель `EN/RU`;
- **Import / Импорт** — загрузка редактируемого проекта;
- **Project / Проект** — скачивание редактируемого `.forge.json`;
- **Export .wsgpack** — скачивание готового канонического пака.

Кнопка экспорта `.wsgpack` заблокирована, пока в паке есть хотя бы одна ошибка. Предупреждения экспорт не блокируют.

### Левая панель типов

Показывает девять типов сущностей и число записей каждого типа:

- Classes / Классы;
- Subclasses / Подклассы;
- Species / Виды;
- Backgrounds / Предыстории;
- Feats / Черты;
- Features / Умения;
- Items / Предметы;
- Spells / Заклинания;
- References / Справочники.

Кнопка `+` создаёт новую сущность выбранного типа.

### Список сущностей

Поиск работает по русскому названию, английскому названию и техническому ID. Подклассы дополнительно сгруппированы по базовым классам. Поиск названия класса показывает связанные с ним подклассы.

Цветная полоска рядом с записью обозначает её статус. Число справа — количество ошибок этой сущности.

### Рабочая область

Здесь находятся формы выбранной сущности. Общие действия:

- **Duplicate / Дублировать** — создаёт независимую копию со статусом `draft`;
- **Delete / Удалить** — удаляет запись после подтверждения;
- **Debug** — открывает отладочное окно выбранной сущности.

### Инспектор

Вкладка **Errors / Ошибки** показывает ошибки и предупреждения выбранной сущности. При открытии Debug из нижней панели можно переключиться на весь пак. Нажатие на проблему открывает соответствующую сущность.

Вкладка **JSON** показывает канонический JSON выбранной сущности, то есть данные в форме, близкой к содержимому `.wsgpack`. JSON доступен только для чтения; кнопка Copy копирует именно этот фрагмент сущности.

Технические значения (`always_on`, `limited_use`, `half_down` и подобные) хранятся только внутри JSON. В редакторе режимы, операции, категории и операторы всегда отображаются понятными локализованными названиями.

Показатель `technical coverage` — ориентировочный индикатор состояния: из 100% вычитается 8% за ошибку и 2% за предупреждение. Это не процент заполненных полей и не гарантия корректности правил D&D.

## 5. Настройки пака

Нажмите карточку пака в верхней панели.

### Pack name

Человекочитаемое название набора. Может содержать пробелы и любой язык.

### Pack ID

Машинный префикс всех сущностей. Допустимы строчные латинские буквы, цифры и `_`; первый символ — буква.

Примеры:

- `srd52`;
- `wsguild_homebrew`;
- `my_campaign`.

После изменения Pack ID нажмите **Done / Готово**. Forge нормализует проект и перестроит ID всех сущностей и внутренних ссылок.

### Version

Версия пака в формате SemVer: `1.0.0`, `2.3.1`, `1.0.0-beta.1`.

Рекомендуется:

- `PATCH` (`1.0.0 → 1.0.1`) — исправление данных без изменения контракта;
- `MINOR` (`1.0.0 → 1.1.0`) — новый совместимый контент;
- `MAJOR` (`1.0.0 → 2.0.0`) — несовместимое изменение ID или структуры.

### Ruleset

ID правил, для которых предназначен пак. Текущее стандартное значение: `dnd5e.2024`.

### Author

Автор или организация. Попадает в манифест и используется как резервный текст атрибуции.

### License

ID лицензии всего пака, например `license.cc-by-4.0` или `license.homebrew`. Лицензия и источник намеренно не дублируются в каждой сущности.

### Системные действия

- **Load complete SRD 5.2.1 project** заменяет текущий проект встроенным демонстрационным проектом SRD. Сначала скачайте резервную копию своего проекта.
- **Clear project** удаляет текущие локальные данные и создаёт пустой стартовый пак после подтверждения.
- **Done** нормализует ID и закрывает окно.

## 6. Общая форма сущности

Каждая сущность содержит:

- название текущего языка;
- автоматически созданный технический ID;
- статус;
- описание текущего языка.

Обязательно заполнить и английское, и русское название. Для этого переключитесь между `EN` и `RU` внутри редактора.

Статусы:

- `draft` — черновик;
- `review` — ожидает проверки;
- `published` — опубликованная стабильная запись;
- `deprecated` — устаревшая запись, сохранённая ради совместимости.

Статус сейчас не исключает сущность из экспорта. Даже `draft` и `deprecated` попадают в пакет.

## 7. Автоматические ID

ID сущности строится так:

```text
pack_id.entity_type.english_name
```

Пример:

```text
srd52.class.wizard
```

ID подсущности строится из ID родителя и её английского имени:

```text
srd52.background.criminal.equipment_set_1
srd52.feat.alert.choice_1
srd52.feature.arcane_recovery.effect_1
```

Правила преобразования:

- используется английское имя;
- буквы переводятся в нижний регистр;
- пробелы и группы специальных символов становятся `_`;
- точки и апострофы удаляются;
- диакритика нормализуется;
- при совпадении добавляется суффикс `_2`, `_3` и далее.

ID нельзя редактировать напрямую. Изменение английского имени перестраивает ID и внутренние ссылки. После публикации не переименовывайте английское имя без осознанной миграции: внешний персонаж или другой пак может продолжать ссылаться на старый ID.

## 8. Рекомендуемый порядок создания пака

1. Настройте Pack ID, имя, версию, правила, автора и лицензию.
2. Создайте справочники, на которые будут ссылаться другие записи.
3. Создайте предметы, включая материальные компоненты заклинаний.
4. Создайте заклинания.
5. Создайте атомарные умения.
6. Создайте черты.
7. Создайте классы и подклассы.
8. Создайте виды и предыстории.
9. Проверьте весь пак через **Debug → Errors**.
10. Скачайте `.forge.json` как редактируемый исходник.
11. Экспортируйте `.wsgpack` для CCL/VTT.

Такой порядок уменьшает число временных пустых ссылок.

## 9. Уровни класса

В разделе **LVL 1–20 progression / Прогрессия уровней** задаются умения, получаемые на каждом уровне.

- номер уровня класса нельзя вводить вручную;
- уровни идут подряд, начиная с 1;
- новый уровень добавляется как предыдущий +1;
- удалить уровень можно кнопкой удаления;
- после удаления уровни класса перенумеровываются последовательно;
- таблица прогрессии автоматически синхронизируется с количеством уровней;
- класс может содержать от 1 до 20 уровней.

У подкласса уровни выдачи умений можно задавать вручную, потому что подкласс не обязан давать умение на каждом уровне.

## 10. Таблица прогрессии класса и Excel

Столбцы таблицы:

- `LVL / УР.` — защищённый номер уровня;
- `PB / БМ` — бонус мастерства;
- `Cantrips / Заговоры` — известные заговоры;
- `Prepared / Подготовлено` — количество подготовленных заклинаний;
- `1–9` — ячейки заклинаний каждого уровня.

Работа как с таблицей:

- клик выбирает ячейку;
- протягивание мышью выбирает прямоугольный диапазон;
- `Shift + клик` расширяет выделение;
- стрелки перемещают активную ячейку;
- `Shift + стрелки` расширяют диапазон;
- `Ctrl/Cmd + A` выбирает всю таблицу;
- `Ctrl/Cmd + C` копирует выделение как TSV, совместимое с Excel;
- `Ctrl/Cmd + V` вставляет прямоугольный блок из Excel;
- `Delete/Backspace` обнуляет редактируемые ячейки диапазона;
- вставка одного значения в выбранный диапазон заполняет им весь диапазон.

Столбец `LVL / УР.` можно выделять и копировать, но нельзя изменять вводом, очисткой или вставкой. Если вставляется 12 столбцов без LVL, Forge автоматически начинает с `PB / БМ`. Если вставляется 13 столбцов с LVL, значения первого столбца игнорируются.

## 11. Импорт и экспорт

### Редактируемый проект `.forge.json`

Кнопка **Project / Проект** сохраняет полную рабочую модель Forge:

- настройки пака;
- обе локализации внутри сущностей;
- визуальные выражения;
- служебные поля редактора;
- все сущности и подсущности.

Именно этот файл следует хранить в Git и импортировать для продолжения редактирования.

### Канонический пакет `.wsgpack`

Кнопка **Export .wsgpack** создаёт файл для CCL/VTT:

- отдельный `manifest`;
- технические `entities` без встроенного текста;
- отдельные словари `localizations.en` и `localizations.ru`;
- типизированные значения эффектов;
- пустой список `assets` для будущих вложений.

`.wsgpack` — конечный артефакт распространения. Текущая версия Forge не использует его как редактируемый исходник. Для повторного открытия сохраняйте `.forge.json`.

### Импорт

Импорт заменяет текущий локальный проект целиком. Перед импортом скачайте резервную копию.

Текущий импорт ожидает объект с `pack` и массивом `entities`, то есть структуру `.forge.json`. Во время импорта Forge:

- переводит проект на `schemaVersion: 2.0.0`;
- удаляет устаревшие `projectId`, `sourceId`, теги и поля лицензии сущностей;
- перестраивает автоматические ID;
- обновляет внутренние ссылки;
- ограничивает уровни класса диапазоном 1–20;
- ограничивает стоимость диапазоном 0–999999 cp;
- переносит часть старых полей в новую структуру.

## 12. Дублирование и удаление

Дублирование:

- делает глубокую независимую копию;
- добавляет `— copy` / `— копия` к названиям;
- ставит статус `draft`;
- создаёт новый ID;
- нормализует ссылки внутри копии.

Удаление сущности не удаляет автоматически ссылки на неё из других сущностей. После удаления откройте проверку всего пака и исправьте предупреждения о пропавших ссылках.

## 13. Мобильная версия

На узком экране навигация открывается кнопкой меню. Формы перестраиваются в одну колонку, однако широкая таблица класса предназначена прежде всего для планшета или компьютера. Для массовой вставки из Excel рекомендуется настольный браузер.

## 14. Что нельзя хранить только в описании

В описании нельзя оставлять механику, которую должен рассчитать CCL/VTT:

- бонус к характеристике, навыку, инициативе, КД, ХП или скорости;
- владение;
- сопротивление, иммунитет или уязвимость;
- выдачу предмета, заклинания или умения;
- ограничение по уровню, условию или ресурсу;
- восстановление после отдыха;
- периодический урон или лечение;
- выбор игрока.

Для этого существуют структурированные поля, выборы, формулы, ресурсы и эффекты. Описание остаётся объяснением для человека.
